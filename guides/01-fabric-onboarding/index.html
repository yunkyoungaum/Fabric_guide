Microsoft Fabric 온보딩 가이드

Capacity 생성부터 Workspace 구성, 테넌트 기능 활성화(Copilot · Data Agent · 온톨로지), 역할·권한 설계까지 — Fabric를 처음 도입하는 팀을 위한 실무 온보딩 안내서. (기준: 2026-09, 공식 문서 반영)

UI 기반 환경 설정 따라 하기 — 익명화된 화면 예시로 관리자 준비부터 참가자 접근 확인까지, 빈 실습 환경을 구성합니다.

이 가이드를 다 읽으면 ① 어떤 용량(SKU)과 라이선스를 살지, ② 워크스페이스를 어떻게 나눌지, ③ Copilot·Data Agent·온톨로지를 켜려면 어떤 테넌트 설정이 필요한지, ④ 권한을 어떻게 설계할지 판단할 수 있습니다.

0. 온보딩 큰 그림

Fabric 도입은 대략 다음 순서로 진행됩니다. 각 단계의 상세는 아래 섹션에서 다룹니다.

① 사전 준비        Entra 테넌트 · 관리자 역할 · 라이선스 계획
        ↓
② Capacity 확보    Azure에서 F SKU 생성 (또는 60일 체험으로 검증)
        ↓
③ Workspace 구성   워크스페이스 생성 → 용량 할당 → 역할 배정 → 도메인 정리
        ↓
④ 테넌트 설정      Copilot · Data Agent · Ontology(Fabric IQ) 활성화
        ↓
⑤ 권한 · 거버넌스  OneLake 보안 · 민감도 레이블 · 감사 로그

1. 사전 준비 (Prerequisites)

1.1 Microsoft Entra 테넌트

  • Fabric는 조직 계정(Microsoft Entra ID) 기반으로 동작합니다. 용량을 만들 Azure 구독은 Fabric 테넌트와 같은 Entra 테넌트에 있어야 합니다.
  • B2B(게스트) 사용자는 용량 관리자(Capacity admin)로 지정할 수 없습니다.

1.2 라이선스의 두 축

Fabric에서 협업하려면 두 가지가 모두 필요합니다 — ① 용량 라이선스(조직 단위) + ② 사용자별 라이선스(개인 단위).

사용자 라이선스무엇을 할 수 있나
FreeFabric가 활성화되고 셀프서비스 가입이 허용된 경우 첫 로그인/가입 과정에서 부여될 수 있습니다. 기존 라이선스를 먼저 확인하고 가입이 차단되면 라이선스 관리자에게 할당을 요청하세요. F(또는 체험) 용량에서 적절한 역할로 Power BI 외 Fabric 아이템을 생성·공유할 수 있습니다. Free만으로는 F64 미만 용량의 공유 Power BI 콘텐츠를 볼 수 없습니다.
Pro내 작업 영역 밖에서 Power BI 아이템을 생성·공유하려면 Pro 또는 PPU(평가 시 해당 개인 체험)가 필요합니다. Free의 내 작업 영역 개인 사용과 조직 내 Power BI 협업을 구분하세요.
Premium Per User (PPU)대부분의 Power BI Premium 기능을 사용자 단위로 제공(대용량 모델, XMLA, 하루 48회 새로 고침 등). PPU는 Fabric 용량을 제공하지 않으므로, Power BI 외 아이템에는 F/체험 용량 또는 Fabric가 활성화된 기존 P 용량의 워크스페이스가 필요합니다.

핵심 규칙 — 조직 사용자가 Fabric/Power BI 서비스에서 공유 Power BI 콘텐츠를 볼 때 F64 미만에서는 각자 Pro/PPU(또는 유효한 개인 체험)가 필요합니다. F64 이상 용량의 워크스페이스는 Free + Viewer로 열람할 수 있습니다. PPU 워크스페이스에는 PPU가 필요하며, 외부 고객용 앱 소유 데이터 임베딩은 별도 라이선스 규칙을 따릅니다.

2. Fabric Capacity 생성

2.1 Capacity와 Capacity Unit(CU)

용량(Capacity)은 Fabric 워크로드가 사용하는 독립적인 컴퓨팅 리소스 풀입니다. 용량의 크기는 CU(Capacity Unit)로 표현되며, 모든 워크로드(데이터 엔지니어링·웨어하우스·실시간·Power BI 등)가 이 CU를 공유합니다.

2.3 Azure Portal에서 용량 만들기

  1. Azure Portal 로그인 → Microsoft Fabric 서비스 검색·선택
  2. Create Fabric Capacity 선택
  3. Basics 탭에서 구독 · 리소스 그룹 · 용량 이름 · 리전(Region) · 크기(SKU) · 용량 관리자 지정 (관리자는 같은 테넌트 소속이어야 함)
  4. Tags → Review + create → 비용·정책 검토 → Create. 배포 완료 후 용량의 Active 상태 확인

사전 요건: Fabric/Power BI 라이선스, 같은 테넌트의 Azure 구독, Microsoft.Fabric 리소스 공급자 등록, 충분한 CU 쿼터, 그리고 다음 Azure RBAC 권한 — Microsoft.Fabric/capacities/ 의 read · write · suspend/action · resume/action.

구매 전 리전별 기능 가용성에서 사용할 워크로드와 미리 보기 기능까지 확인하세요. Fabric 용량 생성이 가능한 리전이라고 모든 기능이 지원되는 것은 아닙니다.

2.4 종량제 vs 예약

  • 종량제(Pay-as-you-go) — 약정 없이 초 단위 과금(최소 1분). 리전별 가격.
  • 예약(Reservation) — 특정 리전에 일정 CU를 1년 또는 3년 약정하면 종량제보다 저렴한 예약 요금 적용. 용량 사용분만 커버하며 스토리지·네트워킹은 별도. 자동 갱신은 기본 꺼짐.

구체적인 예약 할인율(%)은 공식 학습 문서에 수치로 명시되어 있지 않고 Fabric 가격 페이지를 따르며 리전에 따라 다릅니다. 도입 계획 시 가격 페이지에서 직접 확인하세요.

2.5 일시 중지 / 재개와 비용

  • F SKU는 사용하지 않을 때 일시 중지(Pause)해 종량제 컴퓨팅 비용을 아낄 수 있습니다(P SKU는 불가). OneLake 저장 비용과 예약 약정은 중지로 사라지지 않습니다.
  • 일시 중지 시, 남아 있는 누적 초과분·스무딩된 작업이 합산되어 즉시 청구됩니다. 또한 일시 중지는 즉시 스로틀링을 해제하는 수단이기도 합니다.
  • ⚠️ 일시 중지하면 해당 용량의 Fabric 콘텐츠가 사용 불가가 되므로, 사용 중이 아닌지 확인 후 진행하세요.

2.6 스무딩 · 버스팅 · 스로틀링(개념)

Fabric는 30초 단위 시점으로 사용량을 평가합니다.

  • 버스팅(Bursting) — 큰 작업을 빠르게 끝내도록 일시적으로 provisioned 용량보다 많은 컴퓨팅을 사용.
  • 스무딩(Smoothing) — 사용량을 이후 시점으로 평탄화. 대화형은 5~64분, 백그라운드는 24시간에 걸쳐 분산.
  • 스로틀링 — 미래 용량을 과도하게 당겨 쓰면 단계적으로 지연/거부됩니다.
미래 용량 사용영향
≤ 10분보호 구간 — 스로틀링 없음
10분 < 사용량 ≤ 60분새 대화형 요청 제출 시 20초 지연
60분 < 사용량 ≤ 24시간새 대화형 요청 거부(백그라운드는 실행)
> 24시간모든 새 요청 거부

위 표는 일반적인 신규 요청 정책입니다. 이미 실행 중인 작업은 완료할 수 있으며, Real-Time Intelligence는 20초 지연 단계를 적용하지 않는 등 워크로드별 예외가 있습니다. 별도 Autoscale Billing for Spark를 사용하면 해당 Spark 사용량에는 이 공유 CU 풀의 버스팅·스무딩 모델이 적용되지 않습니다.

2.7 체험(Trial) 용량으로 먼저 검증

  • 조직의 체험 허용 정책과 계정 자격을 충족하면 60일 무료. 현재 체험 전용 문서는 F4(4 CU) 또는 F64(64 CU)를 안내합니다. 실제 크기와 만료일은 Admin portal → Capacity settings → Trial에서 확인하세요. Free 사용자 라이선스만 받는 것은 체험 시작이 아닙니다.
  • 모든 워크로드 사용, 워크스페이스 협업, 용량 메트릭 앱, OneLake 1 TB 저장 포함.
  • ❗ 체험에서 제외: Copilot, Data agent / AI functions / AI services, Trusted Workspace Access, Private Link. → AI 기능을 검증하려면 유료 F 용량이 필요합니다.
  • 만료 시 워크스페이스는 Pro로 재할당되고 Power BI 외 아이템은 비활성화됩니다. 콘텐츠는 OneLake에 7일 동안 보관되므로 그 기간 안에 유효한 유료 F/P 용량으로 재할당하세요. 7일이 지난 뒤 복구된다고 가정하지 마세요.

3. Workspace 생성 및 용량 할당

3.1 워크스페이스 만들기

  1. 탐색 창 → Workspaces → New workspace
  2. 고유 이름(필수) · 설명(선택) 입력, 필요 시 도메인 지정
  3. Advanced에서 연락처 목록, 워크스페이스 유형(예전 명칭 "라이선스 모드"), 기본 저장 형식 등 설정

생성 화면의 Apply 후 Workspace settings → Workspace type → Edit → Fabric capacity → 대상 용량 → Apply에서 할당을 확인하세요. 직접 할당하는 운영자는 Workspace Admin이면서 대상 용량의 Contributor 권한(또는 용량 관리 권한)을 가져야 합니다. 용량 담당자가 Contributor permissions에서 사용자/그룹을 허용합니다. Workspace Contributor와 Capacity Contributor는 다릅니다. 기존 아이템의 유형·리전에 따라 이동 제한이 있습니다.

  • Viewer: 읽기 전용. Lakehouse/Warehouse의 SQL 읽기는 기본 ReadData 및 엔드포인트 모드에 따르며, OneLake 직접 읽기는 별도 데이터 권한이 필요합니다(§5). 다른 아이템은 해당 워크로드의 읽기 규칙을 따릅니다.

역할은 개인뿐 아니라 보안 그룹·M365 그룹·서비스 주체에도 부여할 수 있고, 여러 그룹에 속하면 가장 높은 권한이 적용됩니다. 서비스 주체에 역할을 주는 것만으로 모든 기능의 앱 전용 인증이 지원되는 것은 아닙니다. 사용할 API/워크로드의 인증 지원과 테넌트 설정을 별도로 확인하세요.

3.3 워크스페이스 구성 전략

  • 팀·프로젝트·환경(dev/test/prod)별로 분리하고, 역할은 보안 그룹에 부여해 관리 부담을 줄이세요.
  • 도메인(Domain)으로 여러 워크스페이스를 업무 영역(마케팅·영업 등)별로 묶으면 OneLake 카탈로그에서 필터링·거버넌스가 쉬워집니다. 단 도메인 지정은 접근 권한을 바꾸지 않습니다(가시성/접근은 워크스페이스 역할·아이템 권한이 결정).

4. 테넌트 설정 — 기능 활성화

관리 포털의 테넌트 설정에서 기능별 유효 상태와 허용/제외 그룹을 확인하세요. 먼저 Users can create Fabric items를 작성자 그룹에 허용하고 용량의 위임 설정도 확인합니다. 일부 Copilot 설정은 기본 켜짐이므로 불필요하게 조직 전체로 확대하지 않습니다.

4.1 관리 포털 · 테넌트 설정 접근

  1. Fabric 포털(app.fabric.microsoft.com)에 Fabric 관리자로 로그인
  2. 상단 설정(⚙️) → Governance and insights 아래 Admin portal
  3. Tenant settings 선택

공식 문서는 일반 설정에 최대 15분, Data Agent 설정에 최대 1시간의 전파 시간을 안내합니다. 이를 SLA로 보장하지 말고 적용 후 해당 사용자로 유효 설정을 확인하세요.

4.2 보안 그룹 기반 단계적 배포

대부분의 테넌트 설정은 다음처럼 범위를 지정할 수 있습니다 — 조직 전체 사용 / 전체 사용(특정 그룹 제외) / 특정 보안 그룹만 사용 / 특정 그룹 사용(일부 제외). 파일럿 그룹에 먼저 켜고 점진적으로 확대하는 방식으로 안전하게 롤아웃하세요.

4.3 Copilot 및 AI 기능

  • 설정 그룹: "Copilot and AI". 핵심 설정 "Users can use Copilot and other features powered by Azure OpenAI"는 기본 사용(Enabled).
  • 요건: 유료 F2 이상 용량(또는 Power BI Premium P1 이상). 과거의 F64 전용 요건은 더 이상 유효하지 않습니다.
  • Fabric Copilot capacity는 사용자 그룹의 Copilot/Data Agent 사용량을 중앙 청구하는 옵션입니다. 용량 관리자가 사용자 그룹을 할당하며, Pro/PPU 워크스페이스의 Power BI Copilot도 지원합니다. 워크스페이스를 이 용량으로 이전하는 것과 다릅니다. 최소 F2/P1이며 테넌트 홈 리전에 있어야 합니다. F64 미만이라는 이유만으로 별도 지정이 필수인 것은 아닙니다.
  • Azure OpenAI 기반 기능에서 용량이 EU 데이터 경계와 미국 밖에 있으면 지역 외 처리 허용이 필요합니다. Notebook Copilot/Data Agent에는 지역 외 저장 허용도 필요합니다. 두 설정은 기본 꺼짐이며 실제 용량 리전과 보안·개인정보 승인을 확인한 뒤 적용합니다.
  • OpenAI를 Microsoft 하위 처리자로 사용하는 모델의 설정은 Azure OpenAI 설정과 별개입니다. 선택한 기능의 모델 제공자·가용성·계약 요건을 확인하고 별도 승인 후 필요한 설정만 적용하세요.

4.4 Fabric Data Agent

  • 이름/상태: 예전 "AI skills"에서 "Fabric data agent"로 개명, 현재 정식 출시(GA).
  • 요건: 유료 F2 이상(또는 P1 이상) + Copilot 설정이 켜져 있어야 함(Data Agent는 Copilot 기반 기능).
  • 필요한 테넌트 설정: ①"Users can use Copilot and other features powered by Azure OpenAI" ②Data Agent 설정 문서가 요구하는 "Capacities can be designated as Fabric Copilot capacities"(관리자 설정 문서에서는 "Copilot in Fabric capacities") ③EU 데이터 경계·미국 밖 용량은 지역 외 처리·저장 허용. ②는 지정 허용이며 실제 중앙 청구 용량 지정/사용자 할당과 구분합니다. Standalone Copilot in Power BI 설정은 그 경험을 위한 것이며 기본 Data Agent 생성의 필수 설정이 아닙니다.
  • 현재 공식 설정 문서는 별도 "생성·공유" 토글 대신 위 Copilot/Azure OpenAI 설정을 안내합니다. 작성자는 적절한 워크스페이스 역할이 필요하며, 소비자는 에이전트와 원본 데이터의 읽기 권한이 각각 필요합니다. 에이전트 공유만으로 원본 데이터 권한이 생기지 않습니다.
  • 연결 가능한 데이터 소스(최대 5개 조합): Lakehouse · Warehouse · Power BI Semantic Model · KQL Database/Eventhouse · Mirrored Database · Ontology · Microsoft Graph.
  • 실습 준비: 에이전트와 데이터 소스 워크스페이스의 용량 리전을 맞추세요. 현재 Data Agent는 영어 질문·지침·예제를 사용하며 비영어 지원을 가정하지 않습니다. 한국어 가이드라는 이유로 한국어 질의 지원이 보장되지는 않습니다.

4.5 온톨로지 — Ontology (Fabric IQ)

  • Fabric에서 온톨로지는 Fabric IQ(preview) 워크로드의 독립된 "Ontology(preview)" 아이템으로 제공됩니다 — 현업 개념을 엔터티(Entity Type)·속성·관계(Relationship)로 정의하는 시맨틱 레이어입니다. 현재 미리 보기(Preview).
  • 활성화: Fabric 관리자가 테넌트 설정에서 "Enable Ontology item (preview)"를 승인 범위에 켭니다. 온톨로지 그래프는 Fabric Graph 기반입니다. 제공된 UI 예시의 별도 Graph 종속성 안내와 현재 필수 설정 문서가 다르므로 UI 가이드 A8처럼 실제 포털의 요구를 확인하세요.
  • 요건: Fabric 사용 용량의 워크스페이스와 작성 권한이 필요합니다. 정적 데이터는 OneLake, 시계열 데이터는 OneLake/Eventhouse에 준비합니다. 현재 바인딩 문서상 Lakehouse 테이블은 managed 테이블이며 OneLake security와 column mapping이 꺼져 있어야 합니다. 보안이 필요한 운영 소스의 정책을 풀지 말고 승인된 별도 실습 데이터를 사용하세요. Data Agent로 질의하려면 §4.4의 유료 용량·리전·설정 요건도 충족해야 합니다.
  • 여기서 만든 온톨로지는 Data Agent의 데이터 소스로 소비할 수 있습니다(→ 04. Data Agent, 03. 온톨로지 심화).

5. 권한 · 거버넌스 설계

5.1 두 개의 보안 평면

  • 제어 평면(Control plane) — 아이템에 "무엇을 할 수 있나"(생성·구성·공유·관리). 워크스페이스 역할 + 아이템 권한으로 설정.
  • 데이터 평면(Data plane) — "어떤 데이터를 볼 수 있나". OneLake의 경우 OneLake 보안으로 폴더·테이블·스키마·행·열까지 범위를 좁힘.

Admin/Member/Contributor는 이미 데이터 읽기/쓰기 권한을 가지며, OneLake 보안 역할은 주로 Viewer 또는 Read 권한 사용자에게 데이터 접근을 부여할 때 씁니다. OneLake 보안 역할은 Admin/Member가 만들 수 있고 행·열 수준 보안을 지원합니다.

5.2 아이템 단위 공유

워크스페이스 멤버가 아니어도 개별 아이템을 공유할 수 있습니다 — 권한 수준은 Read / ReadData / ReadAll / Write로 나뉘며, SQL 분석 엔드포인트 접근은 엔드포인트 모드(Delegated 등)에 따라 달라집니다.

5.3 민감도 레이블 · 감사

  • 민감도 레이블: Microsoft Purview Information Protection의 레이블·정책을 적용하려면 적절한 Purview 라이선스와 레이블 정의·게시가 필요합니다. Power BI 아이템에 레이블을 적용하는 사용자에게는 Pro/PPU도 필요합니다. 수동·기본 레이블과 다운스트림 상속을 지원하며, 필수 레이블은 Power BI에서 완전 지원, 일부 다른 Fabric 아이템에서 제한적으로 지원됩니다.
  • 감사·모니터링: Microsoft Purview 감사 로그, OneLake 카탈로그의 거버넌스 경험으로 레이블 적용 현황·민감 데이터를 파악.
  • 조건부 접근은 Microsoft Entra/Azure에서, 사용자·라이선스 관리는 M365 관리 센터에서 수행.

Microsoft Fabric Onboarding Guide

From creating a capacity to setting up workspaces, enabling AI features (Copilot · Data Agent · ontology) in tenant settings, and designing roles and permissions — a practical onboarding handbook for teams adopting Fabric for the first time. (As of 2026-09, based on official docs.)

UI-based environment setup walkthrough — use anonymized screenshot examples to prepare an empty workshop environment, from administrator setup to participant access checks.

By the end of this guide you'll be able to decide ① which capacity (SKU) and licenses to buy, ② how to split up workspaces, ③ which tenant settings you need to turn on Copilot, Data Agent, and ontology, and ④ how to design permissions.

1. Prerequisites

1.1 Microsoft Entra tenant

  • Fabric runs on organizational accounts (Microsoft Entra ID). The Azure subscription where you create the capacity must be in the same Entra tenant as your Fabric tenant.
  • B2B (guest) users cannot be designated as a Capacity admin.

1.2 The two axes of licensing

To collaborate in Fabric you need both — ① a capacity license (organization level) + ② a per-user license (individual level).

With appropriate roles, you can create/share non-Power BI Fabric items on F (or trial) capacity. Free alone does not permit viewing shared Power BI content on capacities smaller than F64.
ProCreating/sharing Power BI items outside My workspace requires Pro or PPU (or an applicable individual trial for evaluation). Distinguish Free personal use in My workspace from organizational Power BI collaboration.

Key rule — Organizational users viewing shared Power BI content in the Fabric/Power BI service on capacities smaller than F64 need Pro/PPU (or a valid individual trial). A workspace on F64 or larger supports Free + Viewer access. PPU workspaces require PPU; app-owns-data embedding for external customers follows separate licensing rules.

2. Creating a Fabric Capacity

2.1 Capacity and Capacity Units (CU)

A capacity is a distinct pool of compute resources used by Fabric workloads. Its size is expressed in Capacity Units (CU), and all workloads (Data Engineering, Warehouse, Real-Time, Power BI, etc.) share this CU pool.

2.2 Choosing an SKU

The Power BI mapping is a compute-comparison reference only — it does not imply feature or license equivalence. Microsoft is also consolidating the older Power BI Premium P SKUs into F SKUs, so plan new purchases around F SKUs.

2.3 Creating a capacity in the Azure portal

  1. Sign in to the Azure portal → search for and select the Microsoft Fabric service
  2. Select Create Fabric Capacity
  3. On the Basics tab, set Subscription · Resource group · Capacity name · Region · Size (SKU) · Capacity administrator (the admin must belong to the same tenant)
  4. Tags → Review + create → review costs/policies → Create. After deployment completes, verify the capacity is Active

Prerequisites: a Fabric/Power BI license, an Azure subscription in the same tenant, the Microsoft.Fabric resource provider registered, sufficient CU quota, and these Azure RBAC permissions — Microsoft.Fabric/capacities/ read · write · suspend/action · resume/action.

Before purchasing, check regional feature availability for the intended workloads and previews. The ability to provision capacity in a region does not guarantee every feature is available there.

2.4 Pay-as-you-go vs. reservation

  • Pay-as-you-go — no commitment, billed per second (one-minute minimum). Pricing is regional.
  • Reservation — committing a set number of CUs in a region for one or three years gets you a cheaper reserved rate. It covers capacity usage only — storage and networking are separate. Auto-renew is off by default.

The exact reservation discount (%) is not stated numerically in the official Learn docs; it follows the Fabric pricing page and varies by region. Check the pricing page directly when planning.

2.5 Pause / resume and cost

  • F SKUs can be paused when idle to save pay-as-you-go compute costs (P SKUs cannot). Pausing does not eliminate OneLake storage charges or reservation commitments.
  • On pause, any remaining cumulative overage and smoothed operations are summed and billed immediately. Pausing also immediately clears throttling.
  • ⚠️ Pausing makes that capacity's Fabric content unavailable, so confirm it isn't in use first.

2.6 Smoothing · bursting · throttling (concepts)

Fabric evaluates usage in 30-second timepoints.

  • Bursting — temporarily uses more compute than the provisioned capacity to finish large operations quickly.
  • Smoothing — spreads usage over future timepoints. Interactive over 5–64 minutes, background over 24 hours.
  • Throttling — if you borrow too much future capacity, requests are delayed then rejected in stages.
Future capacity usedImpact
≤ 10 minProtection window — no throttling
10 min < usage ≤ 60 minNew interactive requests delayed 20s at submission
60 min < usage ≤ 24 hNew interactive requests rejected (background still runs)
> 24 hAll new requests rejected

The table describes the general policy for new requests. In-flight operations can finish, and workload exceptions apply: Real-Time Intelligence, for example, skips the 20-second delay stage. With separate Autoscale Billing for Spark, that Spark usage does not follow this shared-CU bursting/smoothing model.

2.7 Validate with a trial capacity first

  • 60 days free, subject to organizational trial policy and account eligibility. The current trial-specific documentation lists F4 (4 CU) or F64 (64 CU). Check the actual size and expiry under Admin portal → Capacity settings → Trial. Obtaining a Free per-user license alone does not start a capacity trial.
  • Includes all workloads, workspace collaboration, the Capacity Metrics app, and 1 TB of OneLake storage.
  • ❗ Excluded from trial: Copilot, Data agent / AI functions / AI services, Trusted Workspace Access, Private Link. → You need a paid F capacity to validate AI features.
  • On expiry, workspaces are reassigned to Pro and non-Power BI items become inactive. Content is retained in OneLake for 7 days; reassign to valid paid F/P capacity within that window. Do not assume recovery after those seven days.

3. Creating Workspaces and Assigning Capacity

3.1 Create a workspace

  1. Nav pane → Workspaces → New workspace
  2. Enter a unique name (required) and description (optional); assign a domain if needed
  3. Under Advanced, set the contact list, workspace type (formerly "license mode"), default storage format, and more

After selecting Apply on creation, verify assignment under Workspace settings → Workspace type → Edit → Fabric capacity → target capacity → Apply. The operator assigning it directly needs Workspace Admin and target-capacity Contributor permissions (or capacity administration permissions). The capacity operator allows users/groups under Contributor permissions. Workspace Contributor and Capacity Contributor are different roles. Existing item types and regions can restrict moves.

3.2 Workspace roles

What you can doAdminMemberContributorViewer
Update/delete the workspace✅
Add/remove people (incl. admins)✅
Add lower-permission members · allow reshare✅✅
Create workspace identity · connect Git✅
Create/modify/delete items · run jobs✅✅✅
Read data via OneLake API/Spark (ReadAll)✅✅✅
View metadata · execution output✅✅✅✅

  • Admin: full control (delete workspace, manage admins, connect Git).
  • Member: can add members, reshare, and read/write data, but cannot delete the workspace or add admins.
  • Contributor: the "builder" role — create/modify/run items, but cannot manage workspace membership. Contributors/Viewers can share items for which they have separate Reshare permission.
  • Viewer: read-only. Lakehouse/Warehouse SQL reads follow default ReadData permissions and endpoint mode; direct OneLake reads require separate data access (§5). Other items follow their workload-specific read rules.

Roles can be granted not only to individuals but also to security groups, M365 groups, and service principals. If a user is in multiple groups, the highest permission applies. Assigning a service principal a role does not imply app-only authentication support for every feature. Check authentication support and tenant settings for the specific API/workload.

3.3 Workspace organization strategy

  • Separate by team/project/environment (dev/test/prod), and grant roles to security groups to reduce management overhead.
  • Use Domains to group workspaces by business area (marketing, sales, etc.) for easier filtering and governance in the OneLake catalog. Note that domain assignment does not change access — visibility/access are determined by workspace roles and item permissions.

4. Tenant Settings — Enabling Features

Check each feature's effective state and included/excluded groups in the admin portal's tenant settings. First allow Users can create Fabric items for the author group and check delegated capacity settings. Some Copilot settings are enabled by default; do not unnecessarily expand access to the entire organization.

4.1 Reaching the admin portal · tenant settings

  1. Sign in to the Fabric portal (app.fabric.microsoft.com) as a Fabric admin
  2. Top Settings (⚙️) → Admin portal under Governance and insights
  3. Select Tenant settings

Official guidance describes up to 15 minutes for general settings and up to one hour for Data Agent settings to propagate. Do not promise this as an SLA; verify effective settings with the affected user afterward.

4.2 Staged rollout via security groups

Most tenant settings can be scoped as — enabled for the whole org / enabled for the whole org except certain groups / enabled for specific security groups only / enabled for specific groups except some. Turn it on for a pilot group first, then expand gradually for a safe rollout.

4.3 Copilot and AI features

  • Setting group: "Copilot and AI". The key setting "Users can use Copilot and other features powered by Azure OpenAI" is on by default.
  • Requirement: a paid F2 or higher capacity (or Power BI Premium P1+). The old F64-only requirement no longer applies.
  • A Fabric Copilot capacity optionally centralizes Copilot/Data Agent billing for user groups. The capacity administrator assigns user groups; this also supports Power BI Copilot in Pro/PPU workspaces. It is not a workspace migration. The capacity must be at least F2/P1 and in the tenant home region. Separate designation is not mandatory merely because the content capacity is below F64.
  • For Azure OpenAI-powered features with capacity outside both the EU data boundary and the US, allow cross-geography processing. Notebook Copilot/Data Agent also require cross-geography storage. Both settings default to off; verify the actual capacity region and security/privacy approval before applying them.
  • Settings for OpenAI-operated models as a Microsoft subprocessor are separate from Azure OpenAI settings. Check the selected feature's model provider, availability, and contractual requirements, and enable only required settings after separate approval.

4.4 Fabric Data Agent

  • Name/status: renamed from "AI skills" to "Fabric data agent", now Generally Available (GA).
  • Requirement: paid F2 or higher (or P1+) + the Copilot setting must be on (Data Agent is a Copilot-powered feature).
  • Required tenant settings: ① "Users can use Copilot and other features powered by Azure OpenAI" ② "Capacities can be designated as Fabric Copilot capacities", required by the Data Agent settings page (called "Copilot in Fabric capacities" in the admin settings page) ③ cross-geography processing/storage for capacities outside both the EU data boundary and the US. ② permits designation; distinguish it from actually designating centralized billing capacity and assigning users. Standalone Copilot in Power BI settings govern that experience, not basic Data Agent creation.
  • Current official settings guidance describes these Copilot/Azure OpenAI controls rather than a separate "create/share" toggle. Authors need appropriate workspace roles; consumers need read access to both the agent and its underlying data. Sharing an agent does not grant source-data access.
  • Connectable data sources (up to 5 in any combination): Lakehouse · Warehouse · Power BI Semantic Model · KQL Database/Eventhouse · Mirrored Database · Ontology · Microsoft Graph.
  • Lab preparation: align the capacity regions of the agent and source workspaces. Currently use English questions, instructions, and examples; do not assume non-English support. A Korean-language guide does not guarantee Korean query support.

4.5 Ontology — Ontology (Fabric IQ)

  • In Fabric, ontology is delivered as a standalone "Ontology (preview)" item in the Fabric IQ (preview) workload — a semantic layer that defines business concepts as entity types, properties, and relationships. Currently in Preview.
  • Enable: a Fabric admin enables "Enable Ontology item (preview)" for the approved scope. The ontology graph is powered by Fabric Graph. The supplied UI example's separate Graph dependency notice differs from the current required-settings page; check the actual portal requirement as described in UI guide A8.
  • Requirements: a Fabric-enabled capacity workspace and authoring permissions. Prepare static data in OneLake and time-series data in OneLake/Eventhouse. Current binding guidance requires Lakehouse tables to be managed, without OneLake security or column mapping enabled. Use approved separate lab data rather than relaxing policies on protected production sources. Querying through Data Agent also requires the paid capacity, region, and settings prerequisites in §4.4.
  • Ontologies built here can be consumed as a data source for Data Agent (→ 04. Data Agent, 03. Ontology deep-dive).

5. Designing Permissions and Governance

5.1 The two security planes

  • Control plane — "what you can do" to an item (create, configure, share, manage). Set via workspace roles + item permissions.
  • Data plane — "what data you can see". For OneLake this is OneLake security, scoped down to folders, tables, schemas, rows, and columns.

Admin/Member/Contributor already have data read/write, so OneLake security roles are mainly used to grant data access to Viewers or users with Read permission. OneLake security roles can be created by Admin/Member and support row- and column-level security.

5.2 Item-level sharing

You can share an individual item even with non-members of the workspace — permission levels are Read / ReadData / ReadAll / Write, and SQL analytics endpoint access also depends on the endpoint mode (Delegated, etc.).

5.3 Sensitivity labels · auditing

  • Sensitivity labels: applying Microsoft Purview Information Protection labels/policies requires appropriate Purview licensing and defined/published labels. Users applying labels to Power BI items also need Pro/PPU. Manual/default labeling and downstream inheritance are supported; mandatory labeling is fully supported for Power BI and partially supported for some other Fabric items.
  • Auditing/monitoring: use Microsoft Purview audit logs and the OneLake catalog governance experiences to understand label coverage and sensitive data.
  • Conditional access is configured in Microsoft Entra/Azure; user and license management in the M365 admin center.
