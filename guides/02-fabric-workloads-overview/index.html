Fabric 워크로드 개요

Fabric의 핵심 아이템과 기능 — Lakehouse · Eventhouse · Power BI Semantic Model · Ontology · Data Agent · Operations Agent · Copilot — 의 관계를 정리할 예정입니다.

작성 중(Draft) — 아래는 이 가이드에서 다룰 목차 틀입니다. 전용 가이드(03·04)도 현재 목차 초안이며, 상세 절차는 추후 작성됩니다.

1. 전체 그림 — OneLake 중심 아키텍처

  • OneLake: 조직 단일 데이터 레이크("데이터의 OneDrive")
  • 저장 → 처리 → 시맨틱 → 소비(AI/BI) 계층 개관
  • 아이템 간 관계 다이어그램(작성 예정)

2. Lakehouse

  • Lakehouse란: Delta/Parquet 기반 파일+테이블 통합 저장소
  • SQL analytics endpoint와 Notebook/Spark 접근
  • 적합한 사용 시나리오(배치·대용량·비정형 포함)

3. Eventhouse

  • Eventhouse/KQL Database: 실시간·시계열 데이터
  • Real-Time Intelligence와 이벤트 스트림
  • Lakehouse와의 역할 비교(데이터 엔지니어링 vs 이벤트 분석 중심, 배치·스트리밍 지원은 중첩됨)

4. Power BI 시맨틱 모델 — 저장 모드 비교

  • Fabric의 Semantic Model은 Power BI 시맨틱 모델이며, 별개의 모델 기술이 아님
  • Import · DirectQuery · Direct Lake 저장 모드의 차이
  • 비교 표: 저장 모드 · 갱신 · 성능 · 라이선스(작성 예정)
  • 언제 어떤 모드를 선택할 것인가

5. Ontology(미리 보기, Fabric IQ)

  • 온톨로지가 시맨틱 모델과 다른 점(개념 수준 요약)
  • 비즈니스 개념(엔터티·관계) 표현 계층
  • → 상세는 03. 온톨로지 심화 가이드

6. Agent와 도우미 — Data Agent · Operations Agent · Copilot

  • Data Agent: 데이터에 대한 자연어 질의 → 상세는 04. Data Agent 가이드
  • Operations Agent: 실시간 데이터 모니터링, 권장 작업 및 구성된 동작
  • Copilot: 지원되는 워크로드에 내장된 생성형 도우미
  • 세 가지의 역할 구분과 조합 패턴

7. 선택 기준 요약

"무엇을 언제 쓰는가"를 한 표로 정리(작성 예정).
